# تقرير الأداء

**الخلاصة:** تحقق هدف LCP أقل من 2.5 ثانية بالاختناق الفعلي (DevTools) على الجوال. **ولم يتحقق بالمحاكاة الافتراضية لـ Lighthouse.** وبقيت مشكلة حقيقية في صفحة البقرة: حظر الخيط الرئيسي نحو 1.3 إلى 1.7 ثانية.

**طريقة القياس:** Lighthouse 12، بناء إنتاج محلي، قاعدة الاختبار، ثلاث مرات لكل صفحة. الخادم على الجهاز نفسه، فلا يمثل زمن شبكة حقيقية. **لم يقس على خادم الإنتاج ولا على هاتف حقيقي.**

## التحليل

| المحور | ما وجد | الإجراء |
|---|---|---|
| **الخطوط (السبب الأكبر)** | 488KB خطوط في كل صفحة، منها خط Amiri غير المستخدم (نحو 200KB) | حذف Amiri، وتقليل أوزان Plex إلى 400 و700، وعدم Preload لخط المصحف. وزن الصفحة الرئيسية من 688KB إلى 372KB |
| تبديل الخط | عنصر LCP نصي، فيعاد احتسابه عند الوصول | Plex صار `optional`. **الأثر:** قد ترى أول زيارة بطيئة خط النظام. خط المصحف بقي `swap` عمداً لدقة الرسم |
| Hydration ومستند البقرة | المستند 444KB، فيه النص وبيانات التلوين مرتين | التلوين يحمل عند فتح وضعه فقط: 358KB. **ما زال كبيراً** لأن النص يأتي في HTML وفي بيانات React |
| حجم JavaScript | 230KB و163KB من إطار React و Next، غير قابلة للتقليل بسهولة | لم يغير |
| الاستعلامات | زمن أول بايت 60–90 مللي ث محلياً | لا عائق محلياً. الخادم الحقيقي لم يقس |
| طلبات API | لا طلب قبل التفاعل في القراءة | الخطوط والتوقيت عند الحاجة |
| الصوت | `preload="none"` ويبدأ بالضغط | لا أثر على LCP |
| الصور | لا صور كبيرة | لا إجراء |
| ما يمنع الظهور | حركة دخول قسم البطل تؤخر احتساب العنصر | أزلت حركة النص في البطل |
| تجربة فاشلة | إلغاء Preload لـ Plex رفع FCP إلى 2.3 ثانية | أعيد |

## ما تبقى

1. **البقرة:** تقسيم السور الطويلة أو عرض تدريجي للآيات، لتقليل Hydration. غير منفذ، لأنه يمس قارئ المصحف ويحتاج اختبار نص دقيق.
2. **المحاكاة في الرئيسية:** العنصر الأكبر معاينة المصحف بخطها. نقل المعاينة أسفل الصفحة أو إظهارها عند الوصول قد ينزلها، وهو قرار تصميم.
3. القياس على الخادم الحقيقي وهواتف فعلية، و Core Web Vitals في الإنتاج.

## أثر تغيير CSP

الـ nonce يجعل كل الصفحات تعرض لكل طلب، وكانت أغلبها كذلك. لم يظهر تأخير ملحوظ محلياً.
