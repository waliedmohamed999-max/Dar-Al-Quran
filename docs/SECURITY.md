# الأمان والخصوصية

> هذا توثيق هندسي وليس رأياً قانونياً. لا يعد النظام متوافقاً قانونياً تلقائياً.

## الضوابط المنفذة

| الخطر | الضابط |
|---|---|
| IDOR وتجاوز الصلاحيات | صلاحية في API ثم RLS في PostgreSQL، ومختبرة مباشرة على الدور المقيد |
| CSRF | كوكي SameSite=Lax وفحص Origin لكل تعديل |
| XSS | تنقية المحتوى عند الحفظ والعرض، و CSP |
| SQL Injection | Prisma واستعلامات ذات معاملات |
| القوة الغاشمة | حد لكل مسار، وحد إضافي لتسجيل الدخول |
| رفع ملفات خبيثة | فحص التوقيع الفعلي للملف والحجم، وتجاهل النوع المعلن |
| تسرب التسجيلات | حاوية خاصة، روابط موقعة لخمس دقائق بعد التحقق، وتسجيل كل استماع |
| بيانات حساسة | تشفير AES-GCM لروابط الاجتماعات، وبلا تاريخ ميلاد |
| تعديل السجلات | سجل التدقيق ونص القرآن غير قابلين للتعديل من دور التطبيق |
| انتحال الشهادات | اعتماد من شخص مخول غير مقدم الطلب، ومفروض بقادح في قاعدة البيانات |

التقرير المفصل بالثغرات وحالتها في [VULNERABILITIES.md](release/VULNERABILITIES.md).

## حماية الأطفال

- لا ترسل تسجيلات القاصر، ولا يستخدم المساعد الذكي، قبل موافقة ولي أمر معتمد ربطه رسمياً، ويمكن سحبها.
- لا يظهر اسم القاصر في التحقق العام من الشهادات.
- مدة الاحتفاظ بالتسجيلات `RETENTION_RECORDING_DAYS` (افتراضياً 180 يوماً) ثم تحذف آلياً، ويشمل ذلك تسجيلات الحديث وتحديد المستوى والاختبارات.
- يمكن لكل مستخدم تنزيل بياناته من صفحة الحساب.

## نقاط ضعف معروفة

- CSP يسمح بـ `unsafe-inline` للسكربتات. الانتقال إلى nonces مطلوب للتشديد.
- `x-forwarded-for` يوثق به في حد المعدل، فيجب أن يستبدله الوكيل العكسي دائماً.
- لا يوجد فحص فيروسات للملفات ولا مصادقة ثنائية للمشرفين.
- لا يوجد حذف ذاتي للحساب، بل عبر طلب للإدارة.
- لم يجر اختبار اختراق مستقل.

## يحتاج إلى مراجعة قانونية قبل الإطلاق

- نصوص الخصوصية والشروط مسودات موسومة بذلك.
- عند الاستضافة في السعودية: مراجعة نظام حماية البيانات الشخصية، ومنها موافقة الولي ونقل البيانات خارج المملكة، ويشمل ذلك إرسال الأسئلة إلى مزود الذكاء الاصطناعي.
- مدد الاحتفاظ والأساس النظامي للمعالجة في بلد التشغيل.
